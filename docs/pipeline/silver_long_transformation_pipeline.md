# Anatel Silver Layer Architecture

## Overview

This document describes the Silver Layer implementation of the Anatel Data Engineering project.

The Silver Layer is responsible for transforming standardized wide-format datasets into a normalized long-format structure suitable for analytical processing, governance, and future consumption by dbt models, analytical marts, and BI tools.

The implementation was developed using PySpark and follows Medallion Architecture principles.

---

# 1. Layer Responsibility

The Silver Layer sits between the raw standardized data and the analytical consumption layer.

```text
RAW (.ods)
    ↓
Wide Standardization
    ↓
SILVER (Long Format)
    ↓
Analytics Engineering (dbt)
    ↓
Marts / KPIs / Dashboards
```

Main responsibilities:

- Transform wide datasets into long format
- Standardize schemas
- Standardize date representations
- Standardize numeric values
- Validate data quality
- Enrich datasets with metadata
- Generate analytical-ready parquet files

---

# 4. Header Identification

Source files contain descriptive rows before the actual dataset.

The pipeline automatically searches for the first valid header row:

```text
GRUPO ECONÔMICO
VARIÁVEL
```

Rows above the identified header are discarded.

Rows without valid business information are also removed.

---

# 5. Schema Standardization

Column names are normalized to guarantee consistency across all datasets.

Applied rules:

- Lowercase conversion
- Accent removal
- Space replacement
- Special character removal
- Underscore standardization

Examples:

| Original | Standardized |
|-----------|-------------|
| Grupo Econômico | grupo_economico |
| Variável | variavel |
| Índice de Reclamações | indice_de_reclamacoes |

---

# 6. Month Column Standardization

Monthly columns are converted into a standard pattern.

Examples:

| Source | Standardized |
|----------|------------|
| 2019/1 | mes_2019_01 |
| 2019-01 | mes_2019_01 |
| 2019/12 | mes_2019_12 |

Pattern:

```text
mes_YYYY_MM
```

This guarantees compatibility across all source files.

---

# 7. Numeric Standardization

The source files use Brazilian numeric formatting.

Examples:

| Original | Standardized |
|-----------|-------------|
| 1.234,56 | 1234.56 |
| 15,8 | 15.8 |
| 0,45 | 0.45 |

Rules:

- Remove thousand separators
- Convert decimal comma to decimal point
- Convert invalid values to null
- Cast values to numeric types

---

# 8. Wide to Long Transformation

The main objective of the Silver Layer is converting monthly columns into records.

Example input:

| grupo_economico | variavel | mes_2019_01 | mes_2019_02 |
|----------------|-----------|------------|------------|
| OI | Reclamações | 100 | 120 |

Output:

| grupo_economico | variavel | competencia | valor |
|----------------|-----------|------------|--------|
| OI | Reclamações | 2019-01 | 100 |
| OI | Reclamações | 2019-02 | 120 |

Transformation performed using Spark SQL `stack()`.

# 14. Current Limitations

Current implementation uses:

```python
df.toPandas().to_parquet(...)
```

for final parquet persistence.

This decision was adopted to maintain compatibility with the local Windows environment during development.

Spark remains responsible for:

- Ingestion
- Transformation
- Validation
- Metadata generation
- Wide-to-long conversion

Future versions may migrate to native Spark parquet writing.
